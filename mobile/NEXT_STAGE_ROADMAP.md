# Offline Knowledge Graph — Proposed Next-Stage Roadmap

## Purpose

The completed roadmap establishes a strong local-first graph foundation: concepts, relationships, evidence context, tag clusters, archives, backups, and guided onboarding. The next stage should prioritize **deeper reasoning**, **faster capture**, and **high-trust review workflows** without introducing login or cloud dependencies.

| Priority | Initiative | User value | Scope |
|---|---|---|---|
| 1 | Evidence review workspace | Lets users inspect all weak, unsupported, or uncited relationships in one focused place. | Add evidence filters, review queue, and confidence summaries. |
| 2 | Graph paths and comparison | Helps users understand how two concepts connect and where the graph has gaps. | Add shortest-path discovery, bridge concepts, and side-by-side concept comparison. |
| 3 | Rich capture inbox | Makes collecting raw notes, links, and quotations frictionless before organizing them. | Add a local inbox, capture templates, promotion into concepts, and batch tagging. |
| 4 | Review and maintenance cycle | Keeps a growing graph useful instead of stale. | Add review reminders, stale-item signals, and a lightweight weekly maintenance dashboard. |
| 5 | Knowledge exchange package | Improves sharing while preserving local ownership. | Add selective export bundles, import conflict previews, and a readable graph report. |

## Recommended Delivery Sequence

The recommended first release is an **Evidence Review Workspace**. It builds directly on the new confidence scores, annotations, quotations, and source URLs. Users could filter to low-confidence relationships, add missing citations, and see whether their graph’s strongest links are actually supported.

The second release should add **Path Discovery and Comparison**. A focused path tool would answer questions such as “How does this observation relate to that method?” and reveal bridge concepts that make the graph more navigable.

The third release should be a **Capture Inbox**. It would provide a fast local landing place for unstructured notes and sources, then guide users to convert selected inbox items into concepts and relationships when ready.

## Discussion Questions

1. Should the next stage prioritize **research rigor** through evidence review, or **speed of capture** through an inbox?
2. Should review cues remain entirely manual, or should the app suggest lightweight local reminders based on inactivity and missing evidence?
3. For knowledge exchange, should the first target be a readable report, a selective JSON package, or both?
