# Adjacent Pairing Transport Research

The selected transport architecture uses optional native adapters behind a local TypeScript boundary. `react-native-zeroconf` 0.14.0 supports publishing and discovering local Bonjour/mDNS services on Android and iOS. Android supports NSD and an embedded DNSSD implementation; Android permissions include network state, Wi-Fi state, and multicast lock access. iOS requires local-network usage text and declared Bonjour service types.

The reviewed `munim-bluetooth` project documents central and peripheral BLE support on Android and iOS, short payload exchange through GATT characteristics, Android Classic Bluetooth RFCOMM, iOS Multipeer Connectivity, and Expo development-build requirements. It is not compatible with Expo Go for native Bluetooth flows. BLE and local-network transports must therefore remain optional native adapters with explicit QR/manual fallback in web and Expo Go.

Security boundary: discovery and pairing advertisements exchange only a short, expiring identity token containing device metadata and a nonce. After the recipient explicitly chooses a nearby publisher, the sender may stream an already encrypted backup bundle over a short-lived local TCP or GATT session authenticated by that token. The transport never receives or transmits the user-held passphrase, and it never sends graph plaintext. The recipient still performs local decryption, conflict preview, and biometric/device-passcode confirmation before recovery or trusted-device registration. Large Bluetooth payloads fall back to local Wi-Fi, QR, or encrypted file sharing.
